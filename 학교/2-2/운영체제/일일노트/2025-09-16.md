운영체재의 메모리를 사용자공간과 커널공간으로 나누어 활용

컴퓨터 시스템 범위
- 응용프로그램층
- 운영체제 층
- 컴퓨터 하드웨어 층

	시스템 계층구조의 특징 
	- 사용자는 응용프로그램이나 운영체제 패키지에 포함된 GUI와 두고 프로그램을 통해 컴퓨터를 활용
	- 하드웨어

캐쉬 메모리
cpu 발전 속도가 너무 빨라 메모리 성능이 따라가지 못함 -> cpu의 프로그램 실행 속도를  올리기 위해 cpu와 메모리사이에 캐시 메모리를 소량 사용

버스: 주소버스, 테이터버스, 제어버스
주소(중요): 저장소에 대한 번지 주소 값이 전달되는 여러선의 다발 cpu는 메모리나 입출력 장치에 값을 읽고 쓸때마다  반드시 주소를 남김 

CPU와 메모리 관계
-CPU: 능동적 소자. 메모리 액세스 시 주소 발생
32비트 운영체제 최대 메모리 4GB(2^32)
64비트 운영체제 최대 메모리 대략 320만테라바이트

CPU 레지스터들
-PC: 다음에 실행 할 기계 명령의 메모리 주소를 저장하는 레지스터
-IR: 실행하기 위해 메모리에서 읽어온 명령이 저장된 레지스터

code
data
heap
stack

CPU 명령 사이클
1. CPU는 PC 레지스터에 저장된 주소 100을 주소 버스에 싣는다
2. 메모리는 주소버스로부터 주소 100을 받고 100번지에 저장된 데이터를 버스에 싣음(mov eax, [300])
3. CPU는 데이터 버스에서 바이너리 값들을 IR 레지스터에 저장, 그후 다음 명령의 번지로 수정

컨텍스트(문맥으로도 표현)
한 프로그램이 실행 중인 일체의 상황 혹은 상황 정보
현재 CPU 안에 들어있는 레지스터 값들

컨태스트 스위칭
CPU가 현재 실행중인 프로그램을 중지하고 다른 프로그램을 실행 할  때 발생
현재 실행중이 프로그램의 컨택스트를 메모리에 저장

멀티코어 CPU
cpu 내부 2개의 프로세스를 포함

운영체제
	커널 코드
	디바이스 드라이버
하드웨어

	운영체제 가 없을시 생기는 문제점
	- 응용프로그램이나 사용자가 직접 하드웨어를 제어해야함
	- 하드웨어에 대한 지식이 필요하며, 충돌, 관리, 보안의 문제 발생

응용프로그램이 직접 하드웨어를 다루지 못하도록 차단
운영체제가 하드웨어를 완전히 독점 장악

운영체제 구성
운영체제 = 커널 + 툴 + 디바이스 드라이버
- 커널 
- 도구(소프트웨어와 GUI)
- 디바이스 드라이버

커널 제공 인터페이스
- 시스템 호출
- 인터럽트: 커널과 하드웨어 사이에 있는 인터페이스

인터럽트 서비스 루틴은 대부분 디바이스 영역에 있음
커널영역에 적재
루틴의 실행응 마치면 하던 작업 계속

응용프로그램의 자원 접근 문제
응용 프로그램이 직접 컴퓨터 자원에 접근하면 충돌과 훼손 발생

자원의 모든 접근을 커널에만 부여

메모리 공간을 사용자공간과 커널 공간으로 분리
실행 모드 또한 분리
응용프로그램 커널 이용시 시스템 호출을 이용에서만 커널코드 이용

사용자 공간 크기
한 응용프로그램의 최대 크기 결정
프로그램코드+데이터(전역변수)+힙+스택 합친 값을 넘으면 안됨

주소공간(가상공간)= 사용자공간+커널공간

특권 명령 예) 인터럽트 끄기

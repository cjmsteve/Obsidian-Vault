## 📚 운영체제 기말고사 핵심 정리 (6장 ~ 12장)

### 🗂️ 6장 스레드 동기화

#### 1. 동기화 기법 (상호배제 구현)

다수의 스레드가 공유 데이터에 동시에 접근할 때 발생하는 문제를 해결합니다.

| **기법**          | **종류**              | **특징**                                                                                       |
| --------------- | ------------------- | -------------------------------------------------------------------------------------------- |
| **락 방식**        | **뮤텍스 (Mutex)**     | `sleep-waiting lock` 기법. 잠김/열림 상태를 가집니다. 한 스레드만 임계구역 진입, 나머지는 큐에 대기하며 잠자기(sleep) 상태로 전환합니다.  |
|                 | **스핀락 (Spinlock)**  | `busy-waiting lock` 기법. 락이 해제될 때까지 무한 루프(spin)를 돌며 기다립니다. 임계구역이 매우 짧을 때 효율적입니다.              |
| **Wait-Signal** | **세마포 (Semaphore)** | 카운터 변수를 사용하여 멀티스레드 사이의 자원을 관리합니다. P 연산($\text{sem\_wait}$)과 V 연산($\text{sem\_post}$)을 사용합니다. |

#### 2. 생산자-소비자 문제

생산자가 공유 버퍼에 데이터를 넣고, 소비자가 꺼내는 문제로, **상호배제, 비어 있는 버퍼, 꽉 찬 버퍼 문제**를 모두 해결해야 합니다.

### 🛡️ 7장 교착상태 (Deadlock)

#### 1. 교착상태 정의

스레드가 자원을 소유한 채, 모두 상대방의 자원을 무한정 대기하는 상태입니다.

#### 2. 코프만 4가지 필요충분조건

교착상태가 발생하기 위한 4가지 조건입니다.

1. **상호 배제 (Mutual Exclusion):** 자원을 한 번에 한 스레드에게만 할당.
    
2. **소유하면서 대기 (Hold and Wait):** 스레드가 자원을 소유하면서 다른 자원을 대기.
    
3. **강제 반환 불가 (No Preemption):** 할당된 자원을 강제로 빼앗지 못함.
    
4. **환형 대기 (Circular Wait):** 자원 요청 관계가 고리(환형)를 형성.
    

#### 3. 교착상태 해결 방법

|**방법**|**설명**|**예시**|
|---|---|---|
|**예방 (Prevention)**|4가지 조건 중 하나를 제거하여 발생 자체를 막음.|소유하면서 대기 제거: 실행 전 자원을 모두 한 번에 할당.|
|**회피 (Avoidance)**|자원 할당 시 교착상태가 발생하지 않도록 미리 검사하여 안전한 상태를 유지.|**Banker's 알고리즘**.|
|**감지 및 복구**|교착상태가 발생하면 이를 감지하고 복구.|스레드 강제 종료, 강제 자원 선점 후 롤백.|
|**무시 (Ignorance)**|발생 확률이 적다고 가정하고 무시.|**타조(Ostrich) 알고리즘**.|

### 💾 8장 메모리 관리

#### 1. 메모리 계층 구조

속도와 용량의 효율을 위해 계층적으로 구성됩니다.

> **CPU 레지스터 > L1/L2 캐시 > L3 캐시 > 메인 메모리(RAM) > 보조 기억 장치**

#### 2. 메모리 주소

- **물리 주소:** 물리 메모리(RAM)에 매겨진 하드웨어 주소.
    
- **논리/가상 주소:** 프로세스나 개발자가 사용하는 주소. MMU(Memory Management Unit)가 물리 주소로 변환합니다.
    

#### 3. 메모리 할당 방식 및 단편화

|**할당 방식**|**특징**|**단편화 문제**|
|---|---|---|
|**연속 메모리 할당**|프로세스를 연속된 공간으로 할당.|**고정 크기:** 내부 단편화 / **가변 크기:** 외부 단편화|
|**분할 메모리 할당**|메모리를 나누어 할당.|**세그먼트 기법** (다양한 크기) / **페이징 기법** (일정한 크기)|

- **홀 선택 알고리즘:** Best-Fit, First-Fit, Worst-Fit 등이 있습니다.
    

### 🧱 9장 페이징 (Paging)

#### 1. 페이징 및 페이지 테이블

**페이징**은 논리 주소를 **페이지(Page)**로 나누고 물리 주소의 **프레임(Frame)**에 매칭시키는 메모리 관리 기법입니다. 페이지 테이블은 이 매핑 정보를 저장합니다.

#### 2. 페이지 테이블의 문제점과 해결책

- **문제 1 (2번 액세스):** 페이지 테이블 룩업 + 데이터 접근으로 속도 저하.
    
    - **해결:** **TLB (Translation Look-aside Buffer)** 사용 (주소 변환을 위한 캐시).
        
- **문제 2 (테이블 낭비):** 테이블 크기가 커져 메모리 낭비 발생.
    
    - **해결:** **멀티레벨 페이지 테이블** (페이지 테이블 자체를 페이징).
        
- **대안:** **역 페이지 테이블 (Inverted Page Table)** 사용. 물리 메모리 크기에 비례하여 테이블 크기가 작아집니다.
    

### ☁️ 10장 가상 메모리

#### 1. 요구 페이징 (Demand Paging)

프로세스가 페이지를 요구할 때만 메모리로 적재합니다. 페이지가 메모리에 없을 경우 **페이지 폴트 (Page Fault)**가 발생합니다.

#### 2. 참조의 지역성 및 스래싱

- **참조의 지역성:** CPU가 짧은 시간 동안 메모리의 특정 구역을 반복해서 참고하는 특성. 이로 인해 **작업 집합 (Working Set)**이 형성됩니다.
    
- **스래싱 (Thrashing):** 페이지 폴트가 과도하게 발생하여 CPU 이용률이 급격히 떨어지는 현상.
    

#### 3. 페이지 교체 알고리즘 (가장 중요)

페이지 폴트 발생 시 제거할 페이지를 결정합니다.

- **최적 교체 (OPT):** **불가능**. 미래에 가장 오랫동안 사용되지 않을 페이지 선택.
    
- **FIFO (First-In, First-Out):** 가장 **오래된** 페이지 선택 및 제거.
    
- **LRU (Least Recently Used):** 가장 **최근에 사용되지 않은** 페이지 선택 및 제거.
    
- **Clock (2차 기회 알고리즘):** FIFO와 LRU의 장점을 절충하여 참조 비트를 활용.
    

### ⏱️ 12장 스케줄링 (Scheduling)

#### 1. 기본 개념

- **선점형 (Preemptive):** 실행 중인 프로세스를 강제로 중단하고 다른 프로세스에게 CPU를 할당할 수 있음.
    
- **비선점형 (Non-Preemptive):** 프로세스가 스스로 CPU를 반납할 때까지 계속 실행.
    

#### 2. 주요 스케줄링 알고리즘

| **알고리즘**        | **특징**                              | **선점/비선점** | **중요 문제점**                                       |
| --------------- | ----------------------------------- | ---------- | ------------------------------------------------ |
| **FCFS**        | 먼저 도착한 순서대로 처리.                     | 비선점        | Convoy Effect (긴 작업 뒤의 짧은 작업 대기).                |
| **SJF**         | 실행 시간이 가장 짧은 작업부터 처리.               | 비선점        | 실행 시간 예측의 어려움. **최소 평균 대기 시간 보장**.               |
| **SRTF**        | SJF의 선점형 버전 (남은 시간이 가장 짧은 작업).      | 선점         |                                                  |
| **우선순위**        | 우선순위가 높은 작업부터 처리.                   | 혼합         | **무한 대기(Starvation)** 발생 가능. **노령화(Aging)**로 해결. |
| **라운드 로빈 (RR)** | 시간 할당량(Time Quantum)을 사용하여 공평하게 분배. | 선점         | 시분할 시스템 적합.                                      |

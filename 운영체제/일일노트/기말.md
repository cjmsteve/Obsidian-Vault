### 2. 생산자-소비자 문제 [cite: 2025-12-02]

생산자 스레드는 데이터를 생성하여 공유 버퍼에 넣고, 소비자 스레드는 공유 버퍼에서 데이터를 꺼내 사용하는 문제로, **동기화 문제의 대표적인 예**입니다. [cite: 2025-12-02]

- **해결책:** 상호배제 (뮤텍스/세마포), 비어 있는 버퍼 문제, 꽉 찬 버퍼 문제를 모두 해결해야 합니다. [cite: 2025-12-02]
## 🛡️ 7장 교착상태 (Deadlock)

### 1. 교착상태 정의 [cite: 2025-11-04]

**교착상태 (Deadlock)**는 스레드가 자원을 소유한 채, 모두 상대방의 자원을 무한정 대기하는 상태입니다. [cite: 2025-11-04]

### 2. 코프만 4가지 필요충분조건 [cite: 2025-11-04]

교착상태가 발생하기 위한 **4가지 필요충분조건**입니다. 이 중 하나라도 만족하지 않으면 교착상태는 발생하지 않습니다. [cite: 2025-11-04]

1. **상호 배제 (Mutual Exclusion):** 자원을 한 번에 한 스레드에게만 할당. [cite: 2025-11-04]
    
2. **소유하면서 대기 (Hold and Wait):** 스레드가 자원을 소유하면서 다른 자원을 대기. [cite: 2025-11-04]
    
3. **강제 반환 불가 (No Preemption):** 할당된 자원을 스레드가 자발적으로 내놓지 않고 강제로 빼앗지 못함. [cite: 2025-11-04]
    
4. **환형 대기 (Circular Wait):** 한 그룹의 스레드들에서 각 스레드가 다른 스레드가 소유한 자원을 요청하는 환형 고리 형성. [cite: 2025-11-04]
    

### 3. 교착상태 해결 방법 [cite: 2025-11-04]

|방법|설명|예시|
|---|---|---|
|**예방 (Prevention)**|4가지 조건 중 하나를 제거하여 발생 자체를 막음. (상호 배제는 근본적으로 제거 불가능) [cite: 2025-11-04]|소유하면서 대기 제거: 실행 전 자원을 모두 파악 후 한 번에 할당. [cite: 2025-11-04]|
|**회피 (Avoidance)**|자원 할당 시 교착상태가 발생하지 않도록 미리 검사하여 안전한 상태를 유지.|**Banker's 알고리즘**. [cite: 2025-11-04]|
|**감지 및 복구 (Detection and Recovery)**|교착상태가 발생하면 이를 감지하고 복구. [cite: 2025-11-04]|스레드 강제 종료, 강제 자원 선점 후 롤백. (비용 부담으로 잘 사용되지 않음) [cite: 2025-11-04]|
|**무시 (Ignorance)**|교착상태 발생 확률이 적다고 가정하고 무시.|**타조(Ostrich) 알고리즘**. 대부분의 운영체제에서 이용. [cite: 2025-11-04]|
## 💾 8장 메모리 관리

### 1. 메모리 계층 구조 [cite: 2025-11-11]

속도와 용량의 효율을 위해 계층적으로 구성됩니다. [cite: 2025-11-11]

> **CPU 레지스터 > L1/L2 캐시 > L3 캐시 > 메인 메모리(RAM) > 보조 기억 장치** [cite: 2025-11-11]

- **참조 지역성 (Locality of Reference)** 덕분에 메모리 계층화는 성공 확률이 높습니다. [cite: 2025-10-21]
    

### 2. 메모리 주소 [cite: 2025-11-11]

- **물리 주소:** 물리 메모리(RAM)에 매겨진 주소. 하드웨어에 의해 고정된 주소. [cite: 2025-11-11]
    
- **논리/가상 주소:** 개발자나 프로세스가 사용하는 주소. 0번지부터 시작하며, CPU 내에서 프로세스를 실행하는 동안 다루는 모든 주소. [cite: 2025-11-11]
    
- **MMU (Memory Management Unit):** CPU로부터 발생되는 논리 주소를 물리 주소로 변환하는 하드웨어. [cite: 2025-11-11]
    

### 3. 메모리 할당 방식 [cite: 2025-11-11, 2025-10-21]

| 할당 방식         | 특징                                            | 단편화 문제                                                    |
| ------------- | --------------------------------------------- | --------------------------------------------------------- |
| **연속 메모리 할당** | 프로세스를 물리 메모리에 연속된 공간으로 할당. [cite: 2025-11-11] | **고정 크기:** 내부 단편화 / **가변 크기:** 외부 단편화 [cite: 2025-11-11]  |
| **분할 메모리 할당** | 메모리를 나누어 할당. [cite: 2025-11-11]               | 세그먼트 기법 (다양한 크기), 페이징 기법 (일정한 페이지 크기). [cite: 2025-11-11] |

## 🧱 9장 페이징 (Paging)

### 1. 페이징 개념 [cite: 2025-12-02]

**페이징**은 메모리 관리 기법 중 하나로, 논리 주소를 **페이지(Page)**라는 일정한 크기의 단위로 나누고, 물리 주소의 **프레임(Frame)**에 매칭시켜주는 기법입니다. [cite: 2025-12-02]

### 2. 페이지 테이블 (Page Table) [cite: 2025-12-02]

논리 주소와 물리 주소를 매핑(Mapping)하는 테이블입니다. [cite: 2025-12-02]

- **문제점 1:** 1번의 메모리 액세스를 위해 2번의 물리 메모리 액세스(페이지 테이블 룩업 + 실제 데이터 접근)가 필요하여 속도가 저하됩니다. [cite: 2025-12-09]
    
    - **해결책:** **TLB (Translation Look-aside Buffer)** 사용. [cite: 2025-12-09]
        
- **문제점 2:** 테이블의 크기가 커져 메모리 낭비가 발생합니다. (4GB, 4KB 페이지 기준 페이지 테이블 크기 220×4 Byte ≈4 MB) [cite: 2025-12-09]
    
    - **해결책:** **멀티레벨 페이지 테이블** 사용. [cite: 2025-12-09]
        

### 3. TLB (Translation Look-aside Buffer) [cite: 2025-12-09]

가상 주소를 물리 주소로 변환하는 속도 증가를 위한 **캐시**입니다. [cite: 2025-12-09]

### 4. 역 페이지 테이블 (Inverted Page Table) [cite: 2025-12-09]

시스템에 단 1개만 존재하며, 물리 프레임 번호로 페이지를 찾는 방식입니다. [cite: 2025-12-09]

- **장점:** 테이블 크기가 프로세스 수나 가상 주소 공간 크기가 아닌 **물리 메모리 크기에 비례**하므로 메모리 낭비가 줄어듭니다. (10개 프로세스 4GB 사용 시, 일반 페이지 테이블 40MB vs 역 페이지 테이블 8MB 예시) [cite: 2025-12-09]
    

### 5. 멀티레벨 페이지 테이블 (Multi-level Page Table) [cite: 2025-12-09]

페이지 테이블 자체를 페이징하여 테이블 낭비 문제를 해결합니다. (예: 2-레벨 페이지 테이블) [cite: 2025-12-09]

## ☁️ 10장 가상 메모리

### 1. 요구 페이징 (Demand Paging) [cite: 2025-12-09]

프로세스가 페이지를 요구할 때(접근할 때)만 메모리로 적재하는 방식입니다. [cite: 2025-12-09]

- **페이지 폴트 (Page Fault):** 요구한 페이지가 물리 메모리(프레임)에 없을 때 발생하는 인터럽트. [cite: 2025-12-09]
    
- **쓰기 시 복사 (Copy-On-Write, COW):** 자식 프로세스 생성 시 부모 프로세스와 메모리를 공유하다가, 쓰기 요청이 발생할 때 복사하여 사용합니다. [cite: 2025-12-09]
    

### 2. 참조의 지역성 (Locality of Reference)과 작업 집합 (Working Set) [cite: 2025-12-10]

- **참조의 지역성:** CPU가 짧은 시간 범위 동안 메모리의 일정 구역을 반복해서 참고하는 특성. [cite: 2025-12-10]
    
- **작업 집합:** 일정 시간 범위 내에 프로세스가 참조한 페이지들의 집합. 참조의 지역성으로 인해 형성됩니다. [cite: 2025-12-10]
    

### 3. 페이지 교체 알고리즘 [cite: 2025-12-10]

페이지 폴트 발생 시, 메모리에서 어떤 페이지(프레임)를 제거할지 결정하는 알고리즘입니다. [cite: 2025-12-10]

- **최적 교체 (OPT):** **불가능**. 미래에 가장 오랫동안 사용되지 않을 페이지를 선택 (최소의 페이지 폴트를 보장하지만 구현 불가능). [cite: 2025-12-10]
    
- **FIFO (First-In, First-Out):** 가장 **오래된** 적재된 페이지를 선택 및 제거. [cite: 2025-12-10]
    
- **LRU (Least Recently Used):** 가장 **최근에 사용되지 않은** 페이지를 선택 및 제거. [cite: 2025-12-10]
    
- **Clock (2차 기회 알고리즘):** FIFO의 단점을 보완. 참조 비트(Reference bit)를 활용하여 페이지에 두 번째 기회를 제공하는 방식 (FIFO + LRU의 절충). [cite: 2025-12-10]
    

### 4. 스래싱 (Thrashing) [cite: 2025-12-09]

프로세스가 작업 집합을 유지하기에 충분한 프레임을 할당받지 못하여 **페이지 폴트가 과도하게 발생하는 현상**입니다. CPU 이용률이 급격히 떨어집니다. [cite: 2025-12-09]

## ⏱️ 12장 스케줄링 (Scheduling)

노트에 내용이 없으므로 시험에 대비하여 중요 내용을 보충합니다.

### 1. 스케줄링의 목적

- **CPU 이용률 최대화:** CPU가 쉬는 시간을 최소화하여 효율적으로 사용.
    
- **처리량 최대화:** 단위 시간당 완료되는 작업의 수 최대화.
    
- **응답 시간/대기 시간 최소화:** 사용자의 요청에 대한 응답 시간을 최소화.
    

### 2. 스케줄링 알고리즘 분류

- **선점형 (Preemptive):** 실행 중인 프로세스를 강제로 중단하고 다른 프로세스에게 CPU를 할당할 수 있음. (인터럽트, 타이머 만료, 우선순위 등에 의해 발생)
    
- **비선점형 (Non-Preemptive):** 프로세스가 스스로 CPU를 반납할 때까지 계속 실행.
    

### 3. 주요 스케줄링 알고리즘

|알고리즘|특징|선점/비선점|장단점|
|---|---|---|---|
|**FCFS (First-Come, First-Served)**|먼저 도착한 프로세스부터 처리.|비선점|간단하지만, 짧은 작업이 긴 작업 뒤에 대기하는 **Convoy Effect** 발생 가능.|
|**SJF (Shortest-Job-First)**|실행 시간이 가장 짧은 프로세스부터 처리.|비선점/선점|**최소 평균 대기 시간**을 보장 (최적의 알고리즘). 하지만, 실행 시간을 미리 정확히 알 수 없다는 단점.|
|**SRTF (Shortest-Remaining-Time-First)**|SJF의 **선점형** 버전. 남은 실행 시간이 가장 짧은 프로세스를 처리.|선점|SJF보다 평균 대기 시간이 더 짧음. 실행 시간 예측의 어려움은 동일.|
|**우선순위 스케줄링**|우선순위가 높은 프로세스부터 처리.|비선점/선점|**무한 대기(Starvation)** 문제 발생 가능. **노령화(Aging)** 기법으로 해결 가능.|
|**라운드 로빈 (Round Robin, RR)**|FCFS 기반에 **시간 할당량(Time Quantum)**을 적용한 선점형.|선점|시분할 시스템에 적합. 시간 할당량이 너무 작으면 컨텍스트 스위칭 오버헤드 증가.|
|**다단계 큐 (Multi-Level Queue)**|프로세스를 특성에 따라 여러 그룹으로 나누고, 각 그룹에 맞는 스케줄링 알고리즘 적용.|혼합|큐 간에 우선순위 부여 (예: 시스템 프로세스, 대화형 프로세스, 배치 프로세스).|
